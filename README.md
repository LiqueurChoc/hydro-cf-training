# Hydro CF 训练插件

项目仓库：[LiqueurChoc/hydro-cf-training](https://github.com/LiqueurChoc/hydro-cf-training)（私有）。本目录是独立项目；早期记录中出现的 MyXCPCFile 路径与 Issue 指向仅为历史背景。

第一次接手请先读[项目接手指南](docs/project-guide.md)：从业务流程理解代码结构、数据与权限边界，再按需进入测试、部署和排障说明。

**使用文档：[完整使用说明](docs/user-guide.md)**（学生、教练、班级管理、安装维护及常见问题）。

学生在 Codeforces 提交，Hydro 负责组赛、历史查重、榜单与独立的训练 rating。首版只实现历史比赛模拟；换题沿用原题位置的分值，没有按题目难度另算 rating 的模式二。

第一次接触软件项目，可先阅读仓库中的[新手入门：从零看懂这个插件](docs/新手入门.md)，跟着一次训练认识各部分，并运行不依赖完整网站的计分实验。

`1.0.0-preview.2` 内部预览：变更见 [CHANGELOG](CHANGELOG.md)，仅用于获准环境的内部测试，不是正式 1.0。首轮为一个真实小班、1–2 名教练；真实训练记录保留到后续版本，明确标记的测试数据可清理。内部测试和真实小班使用均按[试训步骤与结果记录](docs/release-trial.md)验收；自动化合成训练不能代替真实学生整场试训。本轮不创建正式发布标签、不安装到正式 Hydro；将源码托管到私有仓库不代表正式发布。

此前版本已在本机 WSL Ubuntu / Docker、Hydro 5.0.7、Node 22.23.2、MongoDB 7 验证。preview.2 本轮通过 Windows Node 24、独立 MongoDB 8.2.6 临时库及模板浏览器回归，尚未重跑修复后候选的真实 Hydro HTTP/运行时检查。登录后访问 `/cf-training`，也可使用导航栏“CF 训练”。不同 Hydro 域的数据独立，域内拥有独立的“CF 训练管理（教练）”权限的用户进入管理端，其余登录用户默认进入学生端。编辑普通比赛的权限不再授予教练资格。

## 学生与教练权限

管理员在当前域的“管理域 → 角色”中新建 coach（教练）角色，保留普通使用权限；在“管理域 → 权限”中勾选该角色的“CF 训练 → CF 训练管理（教练）”，然后在域用户管理中将指定用户分配到该角色。default 角色不要勾选此权限，这样普通用户默认是学生。角色名称可以自定，插件只检查权限。

- 通用入口 /cf-training 根据当前域权限跳转。
- 学生端 /cf-training/student：个人账号、训练签到、榜单、已解决题目统计、个人 Rating 与 Rating 成长曲线。
- 教练端 /cf-training/coach：训练管理、学生与班级、选赛组赛、结算与档案导出，不显示个人绑定与签到表单。
- 学生访问教练页面或管理 API 会被拒绝；撤销权限后刷新原教练页面返回 403，通过通用入口 `/cf-training` 重新进入学生端。域 root 和拥有全部权限的管理员仍有教练权限。
- 升级后原先仅有 PERM_EDIT_CONTEST 的教练需要由管理员重新授权；不自动扩大任何用户的权限，不改变已有训练数据。

比赛详情 API 对无教练权限的参赛成员使用独立字段白名单，受托班级管理员也遵守同一边界。赛前仅返回比赛基本信息和本人签到状态；开赛后增加实际题目（位置、基础分、比赛编号、题号、题名）、公开模拟说明与本场榜单（UID、handle、名次、得分、罚时、逐题通过/得分、是否可结算）。资格原因与同步问题仅向本人返回；不返回他人接触历史、完整名单、bindingId、发布筛查、换题操作记录、内部快照、扫描证明或纠正审计。已结算的旧快照也经过相同投影；教练仍可查看完整诊断与纠正记录。请求参数中的 uid 不改变当前登录者身份，非成员不能通过班级管理身份读取比赛。

实现兼容性：已核对 Hydro 5.0.7 的 builtin.Permission、PERMS 和 PERMS_BY_FAMILY 注册结构。插件固定使用 BigInt 第 100 位，启动时检查冲突，卸载时移除界面注册；该位不可随意修改，否则已有角色授权将失效。其他插件也不得占用此位。

## 使用流程

1. 学生进入“我的训练”，绑定 CF handle。学生仅允许绑定一次；更换账号须由教练在学生列表点击“更换账号”，操作会记入审计记录。涉及有效草稿或未结算比赛时不能换绑；已取消草稿不阻止换绑。换绑后重新同步、重新确认归属，保留本地 rating。后台验证账号是否存在，首次分页同步全部公开提交和 rated 比赛记录。教练核对账号归属后点击确认；插件不需要 CF 密码或 API 密钥。
2. 教练在“学生管理”维护学生账号，并在“班级管理”维护班级名单。进入“选赛与组赛”后选择一个有权管理的班级，先同步 CF 比赛与题库，再按比赛名称或 ID 搜索筛选，支持每页 20 / 50 / 100 场和翻页。筛选与创建始终使用所选班级当前名单；历史不完整、过期或抓取失败的学生会标记“未知”，不会作为干净历史放行。

3. 输入原比赛 ID，导入历史参照榜；在“后台任务”确认完成后创建草稿。默认沿用原比赛时长，可选择是否计入本地 rating。
4. 在草稿里替换题目，或查看原题难度 ±100 的候选。所有学生使用同一份题目配置，替换题继承原位置基础分。发布后锁定题目和计分规则。难度接近不能保证等价，换题比赛会持续显示标记。草稿错过开赛时间时，教练可改到未来时间再核对配置、重新筛查并发布；不再使用的草稿可取消。取消后原记录与操作者仍可在教练端查看，成员若没有其他有效草稿或未结算训练即可换绑。
5. 学生签到，开赛后从比赛页打开实际题目，在 CF 使用绑定账号提交。赛前接口不返回题目列表。以 Hydro 设定的统一起止时间统计，学生自行开启 CF Virtual 不会改变这个时间窗口。
6. 赛后点击“同步本场所有学生”，等待后台任务完成，再“预览结算 → 确认此次结算”。每名已签到学生都需要一轮在本场结束后启动、实际扫描覆盖至开赛时间或历史末尾的成功同步；普通的近期增量刷新不能替代。页面会逐人指出未就绪的原因。缺席、已有接触记录或被教练设为练习的学生不更新 rating；已签到但零解题、符合资格的学生会正常参与。
7. 发现重测或资格问题时，撤销结算，修正后重新预览。后续本地 rating 会按开赛结束时间重算。已结算榜单保持快照，不自动跟随远端判题改变。

切换参赛班级会立即清空旧筛选结果和翻页，保留搜索输入并要求重新搜索。刷新状态后若该班名单、管理权限或班级本身变化，也须重新搜索；旧请求的迟到结果或错误不会覆盖当前筛选。没有可管理班级时页面会提示先取得授权，不能发起筛选或创建草稿。

长任务在后台执行，页面使用“刷新状态”查看进展；榜单页使用“刷新榜单”。同步请求、扫描代次与分页游标会持久保存；运行中再次请求完整比赛窗口时，后续扫描仍覆盖所需的最早起点，服务重启后可继续。失败任务保留错误记录和尚未满足的扫描范围，排除原因后手动重试仍会覆盖完整范围；操作报错以弹窗提示。

训练详情显示本场已保存的计分规则，赛前不会因此公开题目。后台任务显示对应比赛 ID 或学生 UID/账号及更新时间，换绑前的旧任务不会被标成新账号；这些标签不改变任务权限或执行顺序。

草稿改期只修改开赛时间，保留题目与参赛名单，并清除旧的发布筛查依据；发布时重新筛查。已发布或已结算训练不能使用草稿改期、取消接口。取消记录不能发布、签到、修改资格、同步本场或结算；重复取消不增加审计。取消不删除档案，仍计入单域最多 200 场训练及档案大小上限；JSON 导出包含取消状态和审计，真正的归档与扩容留待后续功能。

## 班级管理与班级榜

“班级管理”是学生和教练共用的入口；教练从“学生管理”选择学生后可打开“添加到班级”弹窗。每个班级独立维护所有者、管理员和学生名单，同一学生可同时加入多个班级。班级所有者或受托管理员可改名、增删学生；每班最多 100 人，允许先创建空班级；学生仍须先绑定 CF 账号才能加入。

- **所有者**：默认为创建教练，可添加或移除班级管理员、删除班级和发起转让。管理员和转让接收者须为当前域的有效用户，可没有全域教练权限。已离域或已删除用户的管理员授权仍可撤销。
- **班级管理员**：只能维护获授权班级的名称、学生名单和查看班级榜。普通学生获授权后仍保留学生主页，在“班级管理”使用受限管理界面，不因此获得组赛、结算、账号确认、换绑或全域导出权限。
- **转让**：所有者点击“转让班级”后，在弹窗中选择当前管理员或通过 UID 查找域内用户；接收者确认后生效，原所有者成为管理员。接收前原所有者继续拥有班级，可取消转让；接收者可拒绝。重新发起或取消后，旧接收请求失效。
- **域管理员**：沿用 Hydro 的“管理域”权限（`PERM_EDIT_DOMAIN`），可管理全部班级并指定或恢复所有者。升级前没有所有者的班级保留原名单，由域管理员指定归属；普通教练不能自动认领。恢复所有者会取消待处理转让。
- **学生切班**：只能查看自己加入的班级，以及自己拥有或获授权管理的班级；转让邀请仅展示接收所需信息。选择保存在当前浏览器、当前域和账号下；班级失效后回退到可见班级。切班不改变个人训练列表、参赛名单、Rating 或成长曲线。
- **班级榜**：按同域共用的本地训练 Rating 降序，同分并列（例如 1、1、3），同分行按 UID 稳定排列；待初始化者不编号、列在最后。显示 Hydro UID、CF handle、已解决题数和同步状态，未同步完整时标注“部分数据”。题数包含当前绑定账号所有已同步 CF 历史的去重 AC，与个人统计口径一致，不限入班后或本站训练；换绑后使用新账号记录。

保存已有班级会更新原班级，以填写的学生名单替换旧名单；并发修改会提示刷新。学生批量添加使用增量合并，不覆盖其他班级关系。删除班级、移除成员与转让均不修改已创建训练、结算或账号。刷新班级榜读取本地记录，不触发 CF 抓取。

## 计分与 rating 的含义

- 普通 CF 计分默认 `max(0.3 × 基础分, 基础分 × (1 - 用时分钟 / 250) - 50 × 之前有效提交次数)`。用时取整分钟；编译失败不扣分；最后一次有效提交决定结果。特殊比赛需在创建草稿时核对衰减参数和扣分。
- ICPC 类型按解题数、总罚时排序，首个 AC 后停止计数，默认每次错误提交罚时 10 分钟。暂不支持 IOI、Gym、交互题特殊积分、marathon 等特殊赛制。
- 本地初始 rating 取首次成功同步时 `user.info` 返回的当前 CF rating，并保存为固定起点；尚未同步时显示“待同步”，没有 CF rating 的未评级账号暂用 1400（标记为默认值）。后续历史同步、换绑账号不会重置起点。升级前已存在结算记录（含已撤销记录）的用户保留旧起点 1400，避免改写历史；没有结算记录的已有账号自动补同步初始化。每个学生分别加入同一份“公开原榜与 ratingChanges 交集”参照池，不把全班一起插入，也不会修改 CF 官方 rating 或 Hydro 自带积分。
- 评分参考 CF 2015 公开方法：预期排名、实际排名的几何平均、反解 rating、取一半变化，再做全体和高分组修正。版本为 `cf-public-2015-v1`，整数二分区间为 `[1, 8000]`。展示排名使用同分最前位置，计算 rating 使用同分最后位置。
- **这是模拟估计，不是官方评分复算。** 原赛选手使用 API 给出的显示 rating；未恢复新账号内部评分，未模拟 hack 行为。换题、历史参照名单不完整及特殊计分均会降低可比性。完整参照快照在导入时冻结，后续再次导入不影响已有比赛。

### Rating 计算与重建

主页、班级榜、结算预览和导出使用同一套后台 Rating 计算。首次读取或评分输入变化后，页面显示“计算中”，不会把旧评分、旧曲线或缺少记录的空曲线当作最新结果；稍后点击“刷新状态”“刷新榜单”或再次预览即可。预览计算完成前不提供确认令牌；导出计算未完成时提示稍后重试，不下载缺少评分的档案。失败后页面显示原因，可稍后刷新重试。班级访问权限与成员仍在每次请求中重新检查。

实现采用进程内有界缓存和 Node worker：版本键从同一次 Mongo 原子档案读取的有效结算输入、固定基线、事件算法版本及缓存格式生成，参照快照 ID 指向不可变的导入数据。结算、撤销、重结算及补齐基线改变有效评分输入时自动切换版本；同步状态、班名和扫描证明不改变评分键。相同评分输入可复用计算，但预览令牌始终根据本次扫描依据、资格、计分输入及档案 revision 重新生成，确认时重新校验。没有独立写入的失效标记，也不在计算完成时覆盖一个无版本的“最新结果”。

每个 Hydro 进程最多执行一个 Rating worker，最多接纳 8 项运行/排队任务，同版本读取合并；结果采用 LRU，最多 16 项、序列化合计 32 MiB，worker 老生代堆上限 256 MiB，单项执行超时 30 分钟。队列满时提示稍后重试；worker 出错或退出后释放任务，失败状态保留至少 1 秒再允许重试。卸载插件会停止 worker。多进程分别缓存，冷启动可能各重建一次；各进程都从权威档案重新确定版本，不依赖进程间失效通知。重启或缓存淘汰后按原输入重建，无需数据库迁移或额外集合。T03 没有改变计分算法、历史最高口径或历史事件；回退会恢复页面同步重算及原有阻塞，已有 T01/T02 的数据与回退限制仍适用。

### Rating 成长曲线（学生主页）

学生端“我的训练”页在账号卡片下方展示成长曲线，只读展示，不参与任何计分。

- 数据只取参与 Rating 结算且未撤销的比赛，按比赛结束时间升序；撤销结算后跟随 `replay` 的重算结果，因此曲线与当前 Rating 始终一致。未签到、被设为练习、有接触记录的学生不出现在该场，不产生数据点。
- 横轴为比赛时间，纵轴为 Rating，折线连接每场赛后积分；背景色带使用 Codeforces 官方段位分段（<1200 Newbie 灰、<1400 Pupil 绿、<1600 Specialist 青、<1900 Expert 蓝、<2100 Candidate Master 紫、<2400 Master 橙、≥2400 Grandmaster 红），与项目既有段位规则一致。
- 虚线为固定起点（`ratingBaselines`），节点颜色为该点所属段位。悬停或点击节点显示比赛名称、日期、赛后 Rating、本场涨跌与名次（名次来自评分引擎，始终可用）。
- 模块上方显示当前 Rating、有效训练历史最高与最近一场变化。最高值取固定起点及当前有效结算按结束时间重放后的赛后 Rating 的最大值；撤销错误结算会重算后续成绩，最高值允许下降，重新结算后也按同一口径计算。例如起点 1400、唯一一场升至 1500，撤销后最高值回到 1400。没有有效结算时显示固定起点，尚未初始化时显示“待同步”。点击节点或明细表中的比赛名跳转到该训练详情页。
- 最高值与成长曲线使用同一版有效评分结果，不保存“曾展示过”的峰值；未确认预览不属于有效训练历史。沿用现有评分缓存的版本校验、失效与重建规则，计算中或失败时不展示旧峰值。无新增数据字段或迁移；旧档案按现有固定起点及有效结算重建，回退旧界面会恢复含糊文案，但不会恢复已撤销成绩的峰值。
- 折线图下方为可折叠的比赛明细表，列出时间、比赛名、赛后 Rating、本场变化，最新一场在最上方。
- 无计分记录时不绘制曲线，只显示起点与明确空状态；只有一场比赛时以单点加起点虚线呈现，不生成虚假连线。初始评分尚未同步时提示等待 CF 同步。

### 已解决题目统计（学生主页）

统计当前绑定账号本地已同步的全部公开提交历史，不限本站训练；同一 `contestId/index`（index 大小写不敏感）合并，包含可识别 Gym。只有至少一条当前保存 verdict 为 `OK` 的题目计入；尚未同步到的记录及未覆盖的早期重测不会自动补齐，页面不请求远端历史。

- 难度按题目 Rating 每 100 分分档，未评级单独统计；题目资料优先使用本地题库，缺失字段分别回退到该题最新有效提交资料。题库同步时间不代表每道题资料都是 CF 最新值。
- 标签保留 CF 英文名。一题的每个不同标签各计一次，因此标签计数总和作为环图的百分比分母；没有可用标签的题每题计入单独的“无标签/标签未知”类别，这不表示题目没有算法知识点。
- 同步未完成或失败时显示已有部分数据并标明状态。统计只描述公开提交记录，不能推断掌握程度或证明独立完成。

资料依据：[CF API](https://codeforces.com/apiHelp)、[API 方法](https://codeforces.com/apiHelp/methods)、[CF 公开 rating 说明](https://codeforces.com/blog/entry/20762)、[CF 比赛规则](https://codeforces.com/blog/entry/4088)。

## “无已知接触记录”的边界

依据公开提交、rated 参赛历史和学生自报进行判断，任何 verdict 的历史提交均算接触；提交类型还能识别有提交记录的虚拟参赛。学生可以补充已见过的题目或比赛。未提交但读过题解、无公开记录的参赛、小号记录及 Div.1/Div.2 不同编号的共用题，首版不能可靠自动识别，选题时仍需学生与教练核实。

学生在“我的训练”查看当前绑定 CF 账号的公开提交题目，按题目去重并分页展示：曾有 AC 的归为“已通过”，其余只要有提交（包括编译错误、待判题）归为“尝试过的题目”。同步未完成时展示已抓取的部分记录；换绑后展示新账号的记录。学生可删除自己手动补充的“已见过”题目或比赛标记；删除不会移除 CF 提交，也不会改写已发布训练的历史检查快照。班级所有者或域管理员可删除班级名单，已有训练及学生账号不受影响。

已发布训练的资格判断保留发布时已确认的接触/参赛证据，并结合后来同步出的赛前证据。发布后、开赛前新增的个人标记也会原子保存在本场；删除、重新添加同一标记不会清除已有证据或自动恢复 Rating 资格。开赛时及之后新增的自报不算赛前证据。历史“未知/过期”不是接触证据，同步及账号确认满足要求后可解除。

误报由具有全域 CF 训练教练权限的用户在训练详情的“本场接触证据与误报纠正”中处理：勾选具体证据、填写理由，保存操作者、时间、训练、学生和证据 ID。普通学生、受托班级管理员均不能使用。纠正只覆盖所选证据；新发现的其他证据仍会影响资格。纠正同一自报后，删除再添加不会撤回纠正。个人历史、签到、仅练习设置、历史完备与赛后扫描条件均保持独立；已结算训练须先撤销结算。任何资格变更都需重新预览，旧 token 会被拒绝。

兼容旧训练：有发布快照时保留其中明确的参赛、接触和 AC 信息，不推断原始来源；没有快照时只使用现有可核实记录，详情会提示无法恢复此前已删除的记录。已结算快照继续冻结，撤销后才按新规则重算。新增数据为发布检查中的 `evidence`、训练中的 `exposureEvidence`（按 UID 保存事实）、`exposureCorrections` 及 `audit` 中的 `correct_exposure`，旧字段缺省按空处理，无新增集合。纠正包含 `evidenceIds`、`reason`、`actor`、`at`，由现有 state revision 原子写入；不改变评分算法、基线或事件顺序，评分缓存仅在有效评分输入变化时重建。回退旧版会忽略本场留存及纠正，重新引入资格问题，不能在回退后继续结算；需配合数据库备份恢复。

默认全量同步每页 500 条、相邻页重叠 25 条；后续从最近同步时间前 24 小时开始增量扫描。每 6 小时例行刷新；开赛前 10 分钟到赛后 1 小时优先每约 60 秒安排刷新。CF 调用统一串行限速，至少间隔 2.1 秒；班级较大时实际延迟会增加。赛后手动同步会覆盖完整比赛窗口，以处理重测。

赛后刷新在后台任务中排队；连续点击和失败后的普通重试都不会缩短尚未满足的扫描窗口。运行中的旧分页结束后，新请求会从第一页按其所需时间起点继续扫描。只有成功扫描到本场所需起点或历史末尾，才会保存绑定账号、代次、启动时间和实际覆盖下界作为结算依据；失败或未完分页不算。不同训练窗口的有效证明会分别保留。预览后再次同步、重测、换绑或更改资格时须重新预览；撤销结算后须重新完整同步本场。升级前未结算数据没有覆盖证明，需要点击“同步本场所有学生”，已结算快照不受影响。回退到旧版会失去这项结算校验，应使用升级前的数据库备份恢复。

## 安装、升级与回退

当前为 `1.0.0-preview.2` 内部预览，不是正式 1.0；获准的内部测试用于完成真实小班试训，正式发布仍须取得相应授权。本版本在 preview.1 上局部修正选赛筛查、刷新调度和操作信息展示，没有改变计分算法、数据集合或恢复 epoch。完整操作、数据清单、旧版兼容限制与恢复命令见[部署与恢复](docs/deployment-recovery.md)。

在获准安装的环境中，使用 PowerShell 7 显式指定目标容器：

```powershell
.\scripts\deploy.ps1 -Distribution Ubuntu -Container <获准的容器名>
# 只对相同恢复 epoch 的备份恢复代码，保留当前其他 addon：
.\scripts\deploy.ps1 -Container <获准的容器名> -Restore <备份编号>
```

脚本先暂存、检查全部产品 JS/worker 和模板，再备份到 `/root/.hydro/cf-training-backups/<编号>/`，停机切换目录。成功要求 PM2 进程在线、插件数据库读取和真实模板渲染成功、健康响应匹配候选构建；失败恢复旧包/配置并重新检查，回退失败也会非零退出。无需额外服务或数据库副本集。

T09 以前的旧包无兼容标记，默认拒绝普通升级。完成离线数据库备份和独立恢复演练后，可在维护窗口用 `-LegacyMaintenance`；若失败，恢复旧代码但保持 Hydro 停止，不能让旧代码处理代次/覆盖证明、接触纠正及 cancelled 数据。详见恢复文档，不得绕过检查伪造兼容标记。

页面 JSON 导出不包含全量提交与参照池，不能代替数据库备份。仍使用 `cftrain_state`、`cftrain_submission`、`cftrain_catalog`、`cftrain_reference`、`cftrain_job`、`cftrain_lock` 六个集合；`scripts/storage-manifest.cjs` 从 Hydro 驱动读取实际 prefix/map 命名空间。离线备份工具 `scripts/database-backup.cjs` 保留 BSON 类型、索引和校验信息，只恢复到独立随机库，绝不自动覆盖真实服务的新写入。
