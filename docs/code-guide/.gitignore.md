# `.gitignore`：哪些内容不该提交

对应源码：[.gitignore](../../.gitignore)

这个文件只被 Git 读取：列出的路径不会进入版本库。它不参与程序运行，但能防止三类东西被误提交。

| 条目 | 对应什么 | 为什么忽略 |
| --- | --- | --- |
| `node_modules/` | 第三方依赖包 | 体积大、可由环境重新提供 |
| `.test-output/` | 测试输出：截图、演示页、`release-session.json` 等临时凭据 | 生成物；凭据不应进仓库 |
| `*.log` | 日志 | 运行痕迹 |
| `.deployment.json` | 部署脚本在目标目录写入的清单，含每次安装随机生成的健康探测密钥 | 属于部署环境状态，含密钥 |
| `dist*/` | 本地打好的候选包（`dist/`、`dist-final/` 等） | 构建产物；需要时用 `scripts/package.cjs` 重新生成 |
| `.workbuddy/` | 外部工具的状态目录 | 与本插件功能无关 |

注意：**打包不是靠 `.gitignore` 过滤的**。[scripts/package.cjs.md](scripts/package.cjs.md) 自己维护一份显式允许清单（根目录文件 + `lib/`、`templates/`、`locales/`、`scripts/`、`test/` 中指定扩展名的文件），所以即使某文件被 Git 忽略，只要在允许清单里仍会进包；反过来，像 `dist*` 这样的目录不在允许清单里，也自然不会进包。

验证：`git check-ignore -v dist/hydro-cf-training-1.0.0-preview.2.tar` 会显示命中 `dist*/` 规则（可在仓库中运行，不产生副作用）。
