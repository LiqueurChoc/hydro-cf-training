# `test/rating-peak.test.js`：成长曲线与"有效训练历史最高"

对应源码：[test/rating-peak.test.js](../../../test/rating-peak.test.js)（对应实现：[lib/rating.js](../../../lib/rating.js)、[templates/cf_training_app.html](../../../templates/cf_training_app.html) 的 `renderRating`）

## 准备了什么场景

这个文件有个特别之处：它把**真实模板里的渲染函数**抽出来，喂给真实评分重放的结果执行，因此同时验证"算法口径"和"页面显示"。

1. **静态口径（A 场景）**
   - 起点 1400、唯一一场升到 1500 → 显示"有效训练历史最高 1500"，并出现"撤销错误结算可能下降"的说明；
   - 没有有效结算 → 最高值回到起点 1400；
   - 唯一一场亏损 → 最高值仍是起点 1400（最高值允许低于当前值）；
   - 未初始化（没有起点）→ 显示"待同步"；
   - `ratingStatus` 不是 `ready` 时 → 不显示旧峰值。

2. **真实 worker 重放（构造的小参照池）**
   - 按**结束时间**而非插入顺序重放：乱序写入的两场结算结果正确；
   - 撤销早期结算后，后一场从起点重算，结果与撤销前不同；最高值相应下降；
   - 重新结算（改分数）后再次重算；
   - 热缓存复用同一版本不重复启动 worker；清空缓存后冷重建结果不变；
   - 全部撤销后最高值回到 1400；删除起点显示"待同步"；补新起点显示新值。

## 为什么值得检查

"历史最高"是一个容易被误解的指标：它不是"曾经展示过的最大值"，而是"当前有效结算按时间重放后的最大值"。早期结算被撤销后，后面的成绩要重新算，最高值允许下降。测试把这个口径固定下来，防止有人用"记录峰值"的简单实现替换它。

## 怎样运行

```sh
cd <插件目录>
node --test test/rating-peak.test.js
```

纯本地；真实 worker + 内存参照替身，不连 Mongo/CF。浏览器布局层面的核对在 [e2e/ui.cjs.md](e2e/ui.cjs.md)（它检查卡片文案与手机宽度不溢出）。

## 容易误解的地方

- 渲染函数是从模板源码里**切片执行**的（`app.slice(...)`）：如果大幅重构 `cf_training_app.html` 的函数名或位置，这个测试会找不到代码，需要同步调整切片范围。
- 用例中的 1400 → 1500 是**自造数据**，用于表达口径；不是某个真实学生的成绩。
- 撤销结算后旧快照仍可查看（榜单冻结），但成长曲线使用有效重放结果——两者不矛盾，测试分别覆盖。
