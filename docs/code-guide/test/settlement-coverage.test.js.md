# `test/settlement-coverage.test.js`：扫描证明与结算覆盖（真实 Mongo）

对应源码：[test/settlement-coverage.test.js](../../../test/settlement-coverage.test.js)（对应实现：[lib/service.js](../../../lib/service.js)）

## 准备了什么场景

**需要 `CFTRAIN_TEST_MONGO_URL`**；用随机临时库。核心问题是：**什么算"赛后完整重扫过这场比赛"**。

1. **窗口覆盖**
   - 只有旧的"最近同步"记录（没有赛后扫描）→ 不能结算，提示"缺少覆盖开赛时间的完整扫描"；
   - 一次只覆盖最近历史的普通刷新 → 仍然不能结算；
   - 发起覆盖开赛时间的全窗口扫描并成功 → 可以结算；
   - CF 把旧的 AC 重判成 WA 后重新全窗口扫描 → 本地记录更新，分数变化；旧的预览 token 失效；
   - 之后再发生一次普通（窄范围）刷新 → 旧的扫描证明仍保留，结算资格不丢。

2. **无效扫描不能冒充覆盖**
   - 在比赛结束前启动的扫描、失败到一半的请求、空历史 → 分别验证不能结算；只有真正读到"历史末尾/所需起点"的空历史才可结算；
   - 换绑后旧证明不再适用（提示"账号已更换"）。

3. **失败重试不缩窗**
   - 全窗口刷新在**第一页就失败**：任务失败、账号标记失败，但请求范围保留；重启服务实例后，普通"刷新历史"仍然以原全窗口范围重试；
   - 在**分页中途失败**：`cycle` 保留，重试继续覆盖完整窗口。

4. **撤销与重结算**
   - 结算后撤销，必须取得"撤销之后启动"的新扫描才能重新结算；
   - 练习标记变化会让旧 token 失效；
   - 仅扫描证明变化时评分缓存不重算（版本不变），但确认 token 一定失效。

## 为什么值得检查

这是全项目最接近"线上事故复盘"的测试文件：它逐条固化了"重测、失败重试、撤销"三种真实情况下，系统如何避免把未重扫的旧成绩结算出去。修改同步、结算、任务队列时，这组用例是最重要的安全网。

## 怎样运行

```sh
cd <插件目录>
CFTRAIN_TEST_MONGO_URL=mongodb://oj-mongo:27017 node --test test/settlement-coverage.test.js
```

没有该变量时全部跳过。测试只操作自己的随机库，并在结束时删除。

## 容易误解的地方

- 文件里的 `finish()` 辅助函数会连续调用 `syncPage` 直到扫描完成；它模拟后台 worker 的执行，不是真实网络。
- "普通刷新不能结算"不是 bug：这是防止 CF 重判后旧成绩被沿用的设计。页面上对应提示"请同步本场所有学生"。
- `tickPage()` 让一个实例抢到锁只处理一个任务，用来复现失败转换路径。
- 该测试通过不代表真实 Hydro HTTP 验收通过；后者见 [e2e/README.md](e2e/README.md)。
