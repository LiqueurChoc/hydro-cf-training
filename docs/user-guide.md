# Hydro CF 训练插件完整使用说明

适用版本：`1.0.0-preview.2`。本文依据当前插件代码、页面及部署脚本编写，面向学生、教练、班级管理者和站点维护者。

学生在 Codeforces（下称 CF）提交代码，Hydro 用于绑定账号、筛选历史比赛、组织训练、同步成绩和计算本地训练 Rating。当前支持历史比赛模拟，所有学生使用同一套题目；可在发布前换题，替换题继承原位置分值。

当前版本仍是内部预览，真实小班试训尚待记录。首轮范围为一个真实小班、1–2 名教练，真实账号绑定、成绩和本地训练 Rating 保留到后续版本。部署及恢复操作见[部署与恢复](deployment-recovery.md)，试训验收见[试训步骤与结果记录](release-trial.md)。

## 1. 入口与角色

登录 Hydro，进入老师指定的域，点击导航栏“CF 训练”。插件按**当前域**的权限选择页面，各域的训练数据独立。

| 入口 | 用途 |
| --- | --- |
| `/cf-training` | 通用入口，按权限进入学生端或教练端 |
| `/cf-training/student` | 学生主页；具有教练权限时会转到教练端 |
| `/cf-training/coach` | 教练管理页，需要“CF 训练管理（教练）”权限 |

以上为插件路由；非默认域请优先通过该域导航进入，保留 Hydro 生成的域路径。

| 身份 | 可以做什么 |
| --- | --- |
| 普通学生 | 绑定本人账号、刷新本人历史、补充接触记录、参加名单内的训练、查看个人统计和可见班级榜 |
| CF 训练教练 | 确认和更换学生账号、组赛、管理训练资格、结算及撤销、导出档案；选赛和创建训练须选择有权管理的班级 |
| 班级所有者 | 管理本班名称和成员，授权管理员，删除和转让班级 |
| 班级管理员 | 管理获授权班级的名称和成员，查看班级榜 |
| 域管理员 | 凭 Hydro 的“管理域”权限管理全部班级，指定或恢复所有者；训练操作仍按 CF 训练教练权限判断 |

这些身份可以叠加。普通学生成为班级管理员或接收班级所有权后，仍使用学生主页，不会自动获得组赛、结算、账号确认或全域导出权限。教练权限在当前域生效，也不意味着自动拥有其他教练的班级。

学生页面包含“我的训练”“班级管理”“Rating 记录”；教练页面包含“训练管理”“学生管理”“选赛与组赛”“班级管理”“Rating 记录”。教练端没有个人绑定和签到表单；需要作为学生参训时，由域管理员安排合适的账号及角色。

## 2. 第一场训练怎么完成

| 顺序 | 操作者 | 页面与动作 | 进入下一步的条件 |
| --- | --- | --- | --- |
| 1 | 管理员 | 安装插件，为指定用户授予教练权限 | 双方可进入正确页面 |
| 2 | 学生 | “我的训练”→“绑定并同步” | 账号验证成功，全历史同步完整 |
| 3 | 教练 | “学生管理”→“确认账号”；“班级管理”→“新建班级”并添加学生 | 归属已核实，班级名单正确 |
| 4 | 教练 | “选赛与组赛”选择参赛班级，同步 CF 比赛与题库，搜索比赛 | 已查看接触情况和未知项 |
| 5 | 教练 | 导入历史参照榜，等待完成，填写时间和规则，创建草稿 | 草稿题目、名单、计分参数正确 |
| 6 | 教练 | 按需换题或改期，点击“锁定题目并发布” | 计分赛全员完成确认和最近 24 小时内的完整历史同步 |
| 7 | 学生 | 打开训练，点击“签到参赛”；开赛后在 CF 提交 | 使用绑定账号及页面上的实际题目 |
| 8 | 教练 | 结束后“同步本场所有学生”，等待任务完成 | 所有已签到者的比赛窗口扫描完成，无待评测提交 |
| 9 | 教练 | “预览结算”→核对→“确认此次结算” | 页面显示本场可结算，比赛已结束 |
| 10 | 学生及教练 | 查看成绩、Rating 记录和班级榜 | 发现问题按第 5 节撤销、修正、重结算 |

“已发布”是保存状态，开赛和结束由时间决定，页面不会另存“进行中”或“已结束”状态。已经结束但未结算的训练仍显示“已发布”。

## 3. 学生操作

### 3.1 绑定账号与确认归属

1. 在“我的训练”的“我的 CF 账号”中输入 **CF handle**，点击“绑定并同步”。输入用户名本身，不填邮箱、密码或个人主页链接。
2. 点击页面右上角“刷新状态”，查看同步进展。首次同步分页读取全部公开提交和 rated 参赛历史，记录较多时需要等待。
3. 将 Hydro UID 与 CF handle 告诉教练，由教练核实后点击“确认账号”。“账号存在”“历史同步完整”“教练已确认”是三个不同条件。

插件不需要 CF 密码或 API 密钥。同一域内，一个 CF handle 不能同时被不同学生绑定。学生仅能自行绑定一次，填错或更换账号需联系教练。

账号卡片显示已扫描记录数、是否完整、上次成功时间、错误信息和本地 Rating。“刷新历史”会请求后台同步；“刷新状态”只更新页面所读到的本地状态。

### 3.2 补充已见过的题目或比赛

展开“补充我已见过的题目或比赛”，选择类型、填写编号，点击“标记已接触”。这用于补充公开提交无法反映的经历，例如读过题解但没有提交。

| 类型 | 支持的输入示例 |
| --- | --- |
| 题目 | `2000/C`、`2000C`、`2000-C` |
| 题目链接 | `https://codeforces.com/contest/2000/problem/C` 或 `https://codeforces.com/problemset/problem/2000/C` |
| 比赛 | `2000` 或 `https://codeforces.com/contest/2000` |

以上只演示输入格式，不是推荐训练题。链接应使用标准 HTTPS 地址，不附带查询参数；当前手动输入只接受比赛编号 1–99999，不接受 Gym 链接。

手动记录旁的“删除”仅删除本人当前的自报标记，不会删除 CF 提交。已发布训练保存的赛前接触证据不会随之消失，也不会自动恢复本场 Rating 资格。确为误报时请教练按第 5.3 节处理。

### 3.3 查看题目记录与统计

“我的 CF 题目记录”支持全部、已通过、尝试过的题目及分页。只要当前保存记录中有 AC，该题归入已通过；否则，有提交的题归入尝试过，包括编译失败和待判题记录。同题重复提交只列一道。

“已解决题目统计”展示难度分布和标签分布。它包含当前账号全部已同步历史，并不限于本站训练。同步尚未完成时，已有记录可以先显示，页面会标记部分数据。统计含义见第 7.3 节。

### 3.4 签到与答题

1. 在“训练场次”点击“查看”，核对训练名称、开始时间、时长和计分规则。
2. 点击“签到参赛”，确认显示“已签到”。已发布训练在结束前都可签到；迟到签到不会重新计时，最好在开赛前完成。
3. 开赛后点击“刷新本场”，从“实际提交题目”打开题目，在 CF 用绑定账号提交。
4. 比赛期间根据需要刷新本人历史，再刷新本场查看本地榜单。成绩随同步更新，不是 CF 的即时推送。

学生在赛前看不到题目列表。若训练有“换题模拟”标记，务必使用详情页中的实际题目，原比赛同位置题目可能已被替换。

有效提交时间是 **Hydro 开始时间 ≤ CF 提交时间 < Hydro 结束时间**。CF Virtual 的个人开始时间不会改变这一窗口；晚签到不补时，结束时刻及之后提交不计本场。计分使用绑定账号的个人提交，团队提交不计入。

未签到者按缺席处理，不更新本场 Rating；当前没有教练补签到入口。已经签到、符合计分资格但零解题的学生仍正常参加 Rating 结算。

### 3.5 赛后查看结果

教练完成同步及结算后，可查看训练详情、“Rating 记录”和成长曲线。成长曲线节点支持悬停或点击，显示该场变化；可从节点或明细表进入训练详情。

没有有效计分训练时显示固定起点，没有虚构的曲线。遇到“计算中”，稍后刷新状态即可；刷新页面本身不会产生新的训练成绩。

## 4. 教练组赛与发布

### 4.1 准备学生账号和班级

在“学生管理”核对 Hydro UID 与 CF handle，账号验证成功后点击“确认账号”。勾选学生可“同步所选学生”或“添加到班级”，后者支持一次选择多个有权管理的班级。

在“班级管理”创建班级或维护名单。学生须已绑定 CF 账号才能加入班级；创建训练前，当前参赛班级中的每个账号都须经教练确认。班级管理操作详见第 6 节。

**学生管理的勾选项用于批量同步和入班；训练名单取“选赛与组赛”中所选班级的全部当前成员。** 创建后再增删班级成员，不会追溯修改该场训练名单。

### 4.2 同步题库和筛选比赛

1. 进入“选赛与组赛”，选择有权管理且非空的“参赛班级”。
2. 点击“同步 CF 比赛与题库”，到“学生管理”下的“后台任务”查看进展，使用“刷新状态”更新。
3. 输入比赛名称、关键词（如 `Div. 2`）或比赛 ID，选择筛选模式和每页数量，点击“搜索 / 筛选”。

| 筛选模式 | 含义 |
| --- | --- |
| 仅无已知接触记录 | 班级中无人历史未知、无人有该场参赛记录、无人有已知题目接触记录时才显示 |
| 全部，优先少量换题 | 保留有冲突的候选，优先历史未知少、参赛人数少、接触题目少的比赛，供教练进一步判断 |

支持每页 20、50、100 场。历史未完整、未经确认、同步失败或距上次成功同步超过 24 小时，会影响“未知”判断；“没有搜索结果”不能直接理解为没有比赛。

切换参赛班级会清空旧结果和分页，需要重新搜索。班级成员、管理权限或班级本身变化后也需要重新搜索。筛选只是已知记录筛查，不能保证每个人实际都没见过题。

### 4.3 导入参照榜并创建草稿

在“导入并创建训练”输入公开比赛 ID 或标准比赛链接，点击“导入历史参照榜”。任务完成后再填写下方表单。

可导入的比赛须已经结束、采用 CF 或 ICPC 计分，并有至少两名可用历史评分参照选手。CF 计分比赛的题目须有基础分。导入失败时先看后台任务错误，不能仅凭题库中存在该比赛就认为可创建训练。

| 表单项 | 如何填写 |
| --- | --- |
| 训练名称 | 1–100 字符，用于列表和历史记录 |
| 原比赛 ID | 已成功导入参照榜的比赛编号 |
| 开赛时间（本机时区） | 未来时间；使用操作者浏览器所在设备的时区 |
| CF 时间衰减参数（分钟） | 默认 250，允许 1–2000；CF 赛制使用 |
| CF 错误提交扣分 | 默认 50，允许 0–1000；CF 赛制使用 |
| ICPC 错误提交罚时（分钟） | 默认 10，允许 0–120；ICPC 赛制使用 |
| 计入本地 Rating | 默认勾选；取消勾选则整场为练习，不更新本地 Rating |

点击“为当前班级创建草稿”。计分类型和比赛时长沿用原比赛，当前界面没有自定义训练时长或切换赛制的入口。创建前应核对特殊比赛参数；草稿详情没有修改这些规则的表单，填错时应取消草稿并重新创建。

导入会冻结参照快照。以后重新导入同一原比赛，不会替换已创建训练所用的参照榜。

### 4.4 换题、改期和取消草稿

草稿详情展示原位置、实际提交题目、基础分和换题操作。可输入题号点击“替换”，或点击“找相近陌生题”查看默认原题难度 ±100 的候选。

替换题须已存在于本地题库，且不能与本场其他位置的实际题目重复。没有原题难度时无法推荐相近题，可手动指定。难度接近仅供筛选参考，教练仍需核对题意、知识点和接触情况。

替换题继承原位置基础分，所有学生使用相同配置；页面持续标记“换题模拟”。换题并不保证与原比赛难度等价，也不会把原比赛的参赛经历自动清除。

草稿错过开赛时间时，先用“修改草稿开赛时间（本机时区）”设为未来时间并“改期”，再核对和发布。改期只改变时间，保留题目、名单和规则，发布时重新筛查。

不再使用的草稿可“取消草稿”。取消记录及操作审计保留，只在教练端可见；不能重新发布，也仍占用训练容量。需要重做时创建新草稿。

### 4.5 发布和练习资格

在“参赛名单与练习资格”可勾选某学生“仅练习，不更新 Rating”。个人练习设置可以在草稿或已发布但未结算时修改。

在开赛前点击“锁定题目并发布”。对于计分赛，**全员**须完成账号确认、完整历史同步且最近成功同步在 24 小时内；将某人设为练习不会绕过整场计分赛的发布检查。

已知有接触记录的学生可以参与训练，但不因此获得 Rating 资格。确实误报时，发布后按第 5.3 节纠正具体证据。

发布后题目、计分规则、时间和参赛名单锁定；当前不能撤回为草稿、修改开始时间或取消已发布训练。发布前应核对当前班级、人员、时区、题目和参数。学生只看到自己名单内的已发布及已结算训练。

## 5. 赛后结算、纠错与导出

### 5.1 完成一次结算

1. 比赛结束后打开详情，点击“同步本场所有学生”。这会请求扫描完整比赛窗口。
2. 到后台任务查看对应学生的状态，等待同步完成，再回到训练点击“刷新本场”。
3. 点击“预览结算”，逐人核对成绩、签到、计分资格和 Rating 变化。尚未就绪时按页面列出的原因处理。
4. 页面显示“本场可结算”且比赛已结束后，点击“确认此次结算”。预览本身不会入账。

每名**已签到学生**都须有一轮在比赛结束后启动、成功扫描至开赛时间或历史末尾的同步。即使该学生只练习、不更新 Rating，也要满足成绩完整条件。普通“刷新历史”完成不保证已覆盖整场；遇到窗口缺失，应使用“同步本场所有学生”。

账号历史或初始 Rating 不完整、同步仍排队/执行、同步失败、缺少比赛窗口扫描、提交仍待评测，都会阻止本场结算。比赛结束前启动、结束后才完成的扫描也不能替代赛后启动的扫描。

Rating 预览可能先显示后台计算中，稍后再预览。出现“预览已变化”或“档案已变化”时，重新预览并核对当前结果，再确认；不要沿用旧预览。

### 5.2 撤销结算与重结算

已结算训练保存成绩快照，不自动跟随 CF 重测结果变化。发现成绩或资格有误时：

1. 点击“撤销结算并重算后续”，训练回到“已发布”，旧结算保留为已撤销记录。
2. 修正练习资格或接触误报；如果 CF 已重测，确认远端判题已经完成。
3. **撤销之后重新点击“同步本场所有学生”**，等待新一轮扫描完成。撤销前的扫描不能直接用作本次重结算依据。
4. 重新“预览结算”并“确认此次结算”。

撤销会重算后续有效训练的本地 Rating，因此当前分数、成长曲线和有效训练历史最高都可能变化。已结算场次不能重复入账。

### 5.3 纠正本场接触误报

教练在已发布训练详情展开“本场接触证据与误报纠正”，选中具体证据，填写 1–500 字符理由，点击“纠正所选证据”。已结算训练必须先撤销。

纠正记录包含操作者、时间、学生及证据，**仅覆盖所选证据**。后来发现的其他赛前证据仍会影响资格；纠正也不替代账号确认、完整同步、签到和取消“仅练习”设置。完成后重新预览。

发布时保存的接触证据、发布后但开赛前新增自报，以及后来同步到的赛前记录，都可能影响本场资格。开赛时及之后新增的手动自报不算赛前证据。学生删除并重新添加同一自报，不会清除已经留存的证据或撤销既有纠正。

旧训练缺少发布快照时，页面会说明只能使用现有可核实记录；系统无法恢复以前已经删除的证据。

### 5.4 导出档案

教练进入“Rating 记录”，点击“导出训练档案 JSON”。计算未完成时稍后重试，导出会包含训练档案与评分结果，班级信息按当前管理权限筛选。

这是教练档案导出，含当前域学生和训练资料，应保存到受控位置。它不是完整数据库备份：完整公开提交、冻结参照池和后台任务等仍需使用第 9 节的备份流程。当前没有将页面 JSON 直接导回的按钮，导出也不会清空记录或释放容量。

<a id="classes"></a>

## 6. 班级管理与班级榜

### 6.1 创建与维护成员

教练在“班级管理”点击“新建班级”，填写名称，可输入初始学生 UID，多个 UID 用逗号分隔，也可先留空。创建者成为所有者，每班最多 100 名学生。

选中班级后，所有者或管理员可在“班级设置”保存名称，使用“学生 UID”表单添加成员，或逐人、批量移除成员。教练也可在“学生管理”勾选学生后“添加到班级”，支持加入多个班级，已在班级中的学生不会重复添加。

同一学生可以同时属于多个班级。成员变更只影响后续组赛名单和班级榜，不改变已创建训练、账号或结算。并发编辑提示“班级已被修改”时，刷新后重新操作。

### 6.2 授权管理员

班级所有者在“管理员 UID”中填写当前域用户 ID，点击“添加管理员”。普通学生也可以被授权。管理员只能维护该班名称和学生名单，不能继续授权别人、删除班级或转让所有权。

所有者可在管理员行点击“移除”撤销授权；原管理员已离域或账号已删除时也可撤销。管理员身份不要求本人是班级学生成员。

### 6.3 转让与恢复所有者

1. 所有者点击“转让班级”，选择当前管理员，或通过 UID 查找当前域其他用户。
2. 核对接收者后点击“确认发起转让”。
3. 接收者在“班级管理”看到邀请，点击“接收班级”后转让生效，也可以拒绝。

接收前原所有者仍管理班级，可取消转让；接收后原所有者自动成为管理员。重新发起或取消转让后，旧邀请失效。

旧版班级没有所有者时，由域管理员在“域管理员：恢复班级所有者”中填写 UID，点击“指定 / 恢复所有者”。恢复所有者同时取消待处理转让。普通教练不能自动认领旧班级。

### 6.4 删除、切班和排名

所有者或域管理员可删除班级。删除移除的是该班级及其成员关系，不删除学生账号、既有训练和 Rating 记录。

学生通过“当前班级”选择已加入、拥有或获授权管理的班级；选择保存在当前浏览器、当前域和账号下。切班只改变班级视图，不改变个人训练列表、参赛名单或 Rating。

班级榜按本地训练 Rating 降序，同分并列，例如 1、1、3；同分行按 UID 排列。尚未初始化者不编号，列在最后。同一学生在同一域的各班共用一个本地 Rating。

班级榜题数是**当前绑定账号全部已同步历史的去重 AC 题数**，不是入班后题数或本班训练题数。同步不完整时标注“部分数据”。“刷新班级榜”读取本地记录，不立即请求 CF。

## 7. 计分、Rating 与统计口径

### 7.1 本场成绩

CF 计分对每题使用最后一次有效提交的结果。最后一次为 AC 时，默认得分为：

```text
max(0.3 × 基础分,
    基础分 × (1 − 用时分钟 / 250) − 50 × 此前有效提交次数)
```

用时按训练统一开始时间计算并取整分钟；250 和 50 可在创建时调整，以详情页保存规则为准。编译失败不扣分。AC 后再次提交若得到有效错误结果，可能覆盖原通过结果；不要把这里的 CF 计分理解为“有一次 AC 就永久保分”。

ICPC 计分按解题数、总罚时排序，每题首个 AC 后停止计数，默认此前每次有效错误提交罚 10 分钟。待评测或无法识别的判题状态会阻止结算。

本站训练榜比较本班本场表现，Rating 预览中的“参照名次”比较的是该学生与冻结历史参照池，两种名次含义不同。

### 7.2 本地训练 Rating

| 名称 | 含义 |
| --- | --- |
| CF 官方 Rating | CF 账号的官方个人评分 |
| 本地训练 Rating | 本插件在当前 Hydro 域内维护的个人训练评分 |
| 题目难度 Rating | CF 题目的难度值，用于题目筛选和统计 |

本地固定起点取首次成功同步时取得的 CF 当前 Rating；未评级账号使用 1400 并标记为默认值。后续同步或换绑不会重置起点。升级前已有结算记录（包括已撤销记录）的账号沿用旧起点 1400，以保留历史计算口径。

每位符合资格的学生分别加入同一份“原公开榜与 ratingChanges 交集”参照池计算，不把全班一起插入。算法采用项目保存的 `cf-public-2015-v1` 版本，是训练模拟估计；未恢复历史新账号内部评分，也未模拟 hack，换题和特殊计分会影响可比性。计算不会修改 CF 官方 Rating 或 Hydro 自带积分。

只有计分训练中已签到、历史核实完成、无有效赛前接触/参赛证据、未设为仅练习的学生才更新 Rating。零解题不构成豁免。

成长曲线只取未撤销的有效计分结算，按比赛结束时间排列。**有效训练历史最高**取固定起点及这些重算后赛后分数的最大值；撤销错误结算后可以下降。比如固定起点 1400，唯一一场升至 1500，撤销后最高回到 1400（此为自造示例）。

后台重建 Rating 时，页面会显示“计算中”“等待计算”或失败原因；稍后刷新即可。重启后重建评分不等于丢失训练记录。

### 7.3 已解决题目与标签统计

“已解决题目”指当前账号已同步提交中有 AC 的去重题目，包含平时练习、正式参赛、虚拟参赛及可识别 Gym。同一比赛编号和题号合并，题号大小写不敏感；不同编号的共用题不自动合并。

难度分布每 100 分一档，没有难度资料的题单独列为未评级。题目资料优先取本地题库，缺失字段回退到提交携带资料，因此可能落后于 CF 当前资料。

一题每个不同标签各贡献一次计数。标签环图的百分比分母是**全部标签计数之和**；无可用标签的题每题计入一次“无标签/标签未知”。它不表示题目没有知识点。

自造示例：两道已解决题分别带有 `dp, math` 和 `dp`，标签计数为 `dp=2, math=1`，环图占比约为 66.7% 和 33.3%，不是各标签占两道题的比例。

这些统计描述公开通过记录，不能证明独立建模或知识点掌握。尚未同步的提交及未重新扫描到的早期重测不会自动补齐。

## 8. 同步与后台任务

| 操作 | 作用 | 何时使用 |
| --- | --- | --- |
| 刷新状态 | 重新读取页面状态 | 看同步、计算和任务进展 |
| 刷新历史 / 学生行“同步” / 同步所选学生 | 请求账号历史同步 | 首次准备、赛前更新、普通失败重试 |
| 同步 CF 比赛与题库 | 更新可搜索比赛及题库资料 | 首次选赛、题库缺失 |
| 导入历史参照榜 | 冻结指定比赛的历史参照数据 | 创建该场草稿前 |
| 同步本场所有学生 | 请求覆盖本场时间窗口的同步 | 赛后结算、撤销后重结算 |
| 刷新本场 / 刷新班级榜 | 读取本地成绩或班级榜 | 同步完成后看结果 |

后台任务区显示类型、目标、状态、更新时间及错误。目标可以是 CF 比赛 ID、学生 UID/账号或题库；换绑前的旧任务会标明历史绑定，不代表新账号同步失败。

状态按“排队中 → 执行中 → 完成”变化，失败时保留错误。排除账号、网络或远端服务原因后，再发起对应操作；当前没有独立的通用“重试全部任务”按钮。分页进度和待扫描范围会保存，服务重启后后台可继续处理。

已有完整历史的账号会被后台到期刷新；它受任务队列和远端请求影响，不保证立即完成。组织训练时仍应以页面实际的完整标记、成功时间和本场扫描结果为准。

## 9. 安装、授权与维护

### 9.1 环境与安装

插件声明支持 Node.js ≥22、Hydro 5.x。现有自动部署入口针对 **Windows PowerShell 7 + WSL Ubuntu + Docker**，目标容器须已运行，容器内有名为 `hydrooj` 的 PM2 进程以及 Hydro 所带依赖。服务器还需要能够访问 CF 公开 API。

当前仓库有其他环境的历史验证记录，但 preview.2 尚待补齐真实 Hydro HTTP/运行时和真实小班试训。不能把历史版本通过记录当成本候选已完成验收。

1. 准备需要安装的候选 tar、相邻 manifest 和 SHA-256 文件，核对压缩包及清单中的文件哈希。
2. 解包到新的空目录，按[部署与恢复](deployment-recovery.md)准备对应升级路径和备份。
3. 在获准维护的环境中，从插件目录运行下列命令，将尖括号占位符替换为实际值：

```powershell
.\scripts\deploy.ps1 -Distribution Ubuntu -Container <目标容器名> -SourceDirectory <已核验的解包目录>
```

| 参数 | 含义 |
| --- | --- |
| `-Container` | 必填，明确指定目标容器 |
| `-Distribution` | WSL 发行版，默认 `Ubuntu` |
| `-SourceDirectory` | 安装源码目录；省略时使用脚本所属插件目录 |
| `-HealthUrl` | 容器内 Hydro origin，默认 `http://127.0.0.1:8888` |
| `-TimeoutSeconds` | 健康等待时间，默认 60，允许 1–300 秒 |

脚本安装到 `/root/.hydro/addons/cf-training`，使用 `/root/.hydro/cf-training-backups/` 保存代码与配置恢复资料。它会校验候选、停止/启动 Hydro 并进行健康检查；PM2 重启成功不等于插件健康验证通过。

没有 Windows/WSL/Docker 的部署方式需要结合实际 Hydro 布局另行适配；本文没有经过核验的通用一键安装命令。该插件 `package.json` 标记为私有包，不应假定可以直接从 npm 安装。

### 9.2 分配教练权限

1. 在当前域“管理域 → 角色”中新建或选择教练角色，保留普通使用权限。
2. 在“管理域 → 权限”中，为该角色勾选“CF 训练 → CF 训练管理（教练）”。
3. 在域用户管理中将指定用户分配到该角色。普通学生的默认角色不要勾选此权限。
4. 用户刷新或重新进入该域“CF 训练”，核对入口是否正确。

插件检查权限而非角色名称，仅有普通比赛编辑权限不能进入教练端。撤销教练权限后，原教练页返回 403 属正常行为，通过通用入口重新进入。

班级管理员通过第 6 节授权，不需要授予全域教练权限。插件使用固定权限位；遇到启动时权限冲突，应检查冲突插件，不能随意改位，否则已有角色授权会失效。

### 9.3 更换学生账号

教练在“学生管理”点击“更换账号”，输入新 handle。学生存在有效草稿或未结算训练时会拒绝换绑：不再使用的草稿先取消；有效训练先按实际情况完成结算。

换绑有审计记录，新账号须重新同步并确认归属，个人题目统计改用新账号；原本地 Rating 起点和训练变化保留。取消的草稿不阻止换绑。应先处理已有训练错误再换绑，避免旧训练重结算时遇到参赛账号已变化。

### 9.4 备份、升级和恢复

详细命令、停写要求和实际集合映射统一见[部署与恢复](deployment-recovery.md)。维护前区分三类资料：

| 资料 | 能恢复什么 |
| --- | --- |
| 页面 JSON 导出 | 查看训练档案和评分结果，不能完整恢复插件数据库 |
| 部署脚本的代码/配置备份 | 恢复兼容插件代码和 addon 配置，不自动回滚数据库 |
| 六个插件集合的离线备份 | 提交、参照池、训练档案、队列等完整插件数据；还需 Hydro 本身的账号、域和配置 |

相同恢复兼容边界内的旧版本可按备份编号执行：

```powershell
.\scripts\deploy.ps1 -Container <目标容器名> -Restore <备份编号>
```

首次安装的“无旧插件”备份、没有兼容标记的老版本，不能直接用该入口恢复。旧版升级所用 `-LegacyMaintenance` 是停机维护流程，须先完成停写、离线备份和独立库恢复验证，不能用于绕过兼容性拒绝。

当前数据包含真实学生内测试训记录，升级时应保留。整个 Hydro 的数据库、文件与配置仍需站点自己的备份方案。

### 9.5 文档与安装包

在插件根目录执行 `node scripts/package.cjs --list` 可查看打包文件清单，本说明随新包分发。执行 `node scripts/package.cjs <新的输出目录>` 可生成 tar、manifest 和 SHA-256；相同目标文件名不会覆盖。

修改源码或包内文档后，原有候选压缩包不会自动更新。需要分发当前内容时，应重新打包、核对哈希并验证实际候选；不要把新文档当成旧包已经包含的内容。

## 10. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 看不到“CF 训练”或打开 404 | 核对是否登录、是否在正确域、插件是否安装并加载成功；由维护者查看部署结果 |
| 访问教练页或提交操作返回 403 | 核对当前域权限；重新登录并打开通用入口，刷新过期页面后重试 |
| 账号已存在但不能确认 | “确认账号”要求后台验证成功，先同步并查看错误；确认归属仍需教练人工核实 |
| 不能自行重新绑定 | 学生只允许绑定一次；联系教练“更换账号” |
| 提示该账号已被其他学生绑定 | 核对当前域已有绑定及账号归属，不能共用同一 CF handle |
| 不能更换账号 | 处理阻塞的有效草稿或未结算训练，取消无用草稿后重试 |
| 选赛没有可管理班级 | 新建班级或由所有者授权；旧班级先由域管理员指定归属 |
| 班级名单里找不到学生 | 确认当前域正确，学生已绑定 CF；按 Hydro UID 添加，不能将 CF handle 当 UID |
| “仅无已知接触记录”没有结果 | 先切换“全部”看未知/接触情况；完成全员确认和新近完整同步，再重新搜索 |
| 创建草稿提示先导入 | 题库同步不等于参照榜导入；等待指定比赛导入任务完成 |
| 导入提示缺少历史评分参照 | 该场缺少所需公开参照数据，选择其他可用比赛；取消 Rating 勾选也不能绕过当前导入条件 |
| 替换题找不到或候选为空 | 同步题库；原题无难度时手动选题；同时检查当前名单的历史状态和接触记录 |
| 发布提示历史未知或过期 | 确认全员账号并完成最近 24 小时内的完整历史同步，再发布 |
| 学生看不到训练 | 核对创建时的成员名单和发布状态；后来加入班级不会自动加入旧训练 |
| 赛前没有题目 | 正常隐藏；开赛后“刷新本场”。若仍异常，核对统一开始时间及设备时区 |
| 在 CF 已 AC，但本场没有得分 | 请求同步，再检查账号、实际题目、提交时间、是否团队提交及该场计分规则；CF 模式还需检查最后一次有效提交 |
| 比赛结束却仍显示“已发布” | 这是未结算状态；按第 5.1 节完成同步和结算 |
| 已同步却仍不能结算 | 普通刷新或赛前启动的同步未必满足比赛窗口要求；赛后重新“同步本场所有学生”，按逐人原因处理 |
| 设为练习仍阻塞结算 | 已签到练习者也要满足成绩完整条件；完成其同步和判题后再预览 |
| 删除已见过记录后仍不计分 | 本场赛前证据已保留；确属误报时由教练纠正具体证据 |
| Rating 不变化 | 查看是否练习场、未签到、已有接触、仅练习、尚未结算或变化值本来就是 0 |
| Rating 或导出显示计算中 | 等待后台计算，刷新状态或重新预览/导出；失败时查看原因后重试 |
| 撤销后历史最高下降 | 最高值按当前有效训练重算，包含固定起点，下降符合定义 |
| 题数和 CF 页面不一致 | 查看是否部分同步、是否换绑、题目去重口径及早期重测；班级榜刷新不会触发远端抓取 |
| 修改班级/确认结算提示数据变化 | 有并发更新；刷新班级或重新预览，核对新结果后提交 |
| 删除班级后训练还在 | 删除班级不删除既有训练、账号或 Rating，这是保留历史的预期行为 |
| 达到 200 场或档案大小上限 | 导出保存并安排存储扩容/迁移；取消草稿、删班或导出不会释放训练容量 |

反馈问题时提供插件版本、Hydro 域、操作角色、训练名称/编号、操作时间、原始错误提示及相关任务状态。学生身份由教练在受控渠道核对，不提交密码、会话、部署探针密钥或数据库连接凭据。

## 11. 当前限制与资料依据

- 仅支持公开历史比赛的 CF/ICPC 模拟；没有按替换题难度另算 Rating 的第二种模式。IOI、Gym 组赛、交互题特殊积分、marathon 等不在当前支持范围；统计可识别 Gym 不等于支持 Gym 组赛。
- 接触判断使用公开提交、rated 参赛历史和手动自报。未提交的阅读经历、未公开记录、小号经历以及不同比赛编号的共用题不能可靠自动识别。
- 每班、每场最多 100 名学生，单域最多保留 200 场训练；取消记录也占容量，档案约达 12 MB 时拒绝继续写入。当前没有归档清理、CSV 报表或复盘功能。
- 已发布训练不能改期、撤回或取消；无学生取消签到、教练补签到、页面 JSON 导入恢复入口。
- 本说明核对的是当前代码行为；未在本次文档编写中完成真实 CF、Hydro 运行时或真实学生整场试训。真实使用验收按[试训记录](release-trial.md)填写。

**AI补充**：本文是根据仓库实现整理的操作说明。本次未读取学生原始学习笔记，不新增“笔记依据”核实声明。**待老师确认**：真实小班能否顺畅完成账号准备、统一时间训练、同步结算及异常处理，以试训结果为准。
