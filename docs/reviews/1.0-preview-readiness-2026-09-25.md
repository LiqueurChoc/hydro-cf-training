# 1.0 Preview 上线前审阅

日期：2026-09-25。对象：`hydro-cf-training` 完整工作树。定位：`1.0.0-preview.1` 仅用于获准环境内部测试，不是正式 1.0。正式版门槛仍为真实小班整场试训通过、结果记录完整并取得明确发布授权。

## 结论

在当前离线验证范围内，没有发现新的 P0/P1 产品缺陷。Windows Node v24.19.0 执行 `node --test test/*.test.js` 为 62 项通过、0 项失败、20 项外部服务测试跳过；45 个 JS/CJS 文件语法检查通过。跳过项包含真实 Mongo、部署运行时和实时 CF，不能据此宣布完整技术验收或真实使用验收。

`1.0.0-rc.2` 包曾与当前源码逐文件哈希一致，但本轮调整版本、状态文档与包边界测试后必须重新生成 preview 包。Preview 包只用于内部测试；测试通过后的正式 `1.0.0` 必须重新设置版本、生成清单和 SHA-256，并重新核对交付物。

## 发布边界

- 冻结现有组赛、签到、历史筛查、结算、班级授权、学生统计、恢复与部署闭环。
- 1.0 前只处理阻塞缺陷、数据安全、恢复和发布可追溯性，不继续扩展业务功能。
- 正式源码提交包含候选清单中的运行代码、测试、恢复工具和项目文档；`.workbuddy/`、`dist*/`、`.test-output/` 等生成物保留在本机但不进入提交或安装包。
- Preview 阶段不创建正式 Git tag、不推送、不安装到正式 Hydro。

## 后续建议

1. **1.1 优先补充同步进度与原范围重试面板。** 后台状态和扫描正确性已经存在，但教练仍缺少直观的待处理人数、覆盖范围与失败原因视图。
2. **1.1 补容量提示与可恢复归档。** 当前单域 200 场、状态文档 12 MB 限制已有硬保护，但缺少余量展示和安全归档流程。
3. **1.1 再考虑班级报表、CSV 与赛后复盘。** 这些功能有价值，但不应成为 1.0 完成门槛。
4. **暂不增加推荐系统、更多数据源、IOI/Gym 特殊计分或存储分片。** 当前用户规模和数据上限尚不能证明这些复杂度的收益。

## 非阻塞维护项

- `lib/service.js` 同时承担队列、同步、参照导入、筛查、结算和评分协调，适合在 1.1 后按状态机边界逐步拆分，不宜在 preview 前重构。
- `importContest` 先写参照分片再写快照元数据；中途失败可能留下未被引用的分片。它不改变比赛结果，但长期失败重试会积累垃圾数据，应与容量归档一起处理。
- 当前安装包包含测试与恢复工具，便于按同一清单复验，也扩大了交付文件面。该取舍已接受给 1.0；生产包与测试包拆分排到后续版本。

## 正式 1.0 前门槛

1. 在获准环境按 `docs/release-trial.md` 完成内部测试和真实小班整场试训。
2. 记录 preview 包 SHA-256、环境、备份恢复编号、真实同步/榜单/结算、学生操作与异常。
3. 修复试训发现的阻塞问题，并对同一份最终源码重新执行本地、真实 Mongo/Hydro 与必要的 CF 验证。
4. 将版本改为 `1.0.0`，重新打包、核对清单和 SHA-256；取得明确授权后才创建正式标签和部署。
