## Standards

### S1 · P2 · 自定义索引的 BSON 条件在恢复时改变类型

- 位置：[database-backup.cjs](../../scripts/database-backup.cjs)，第 31—38、58—60 行。
- 文档约定：[部署与恢复](../deployment-recovery.md)第 93 行承诺备份包含索引并保留 BSON 类型。
- `listIndexes()` 的结果使用普通 `JSON.stringify` 写入 `backup.json`，恢复时普通 `JSON.parse` 后直接传入 `createIndexes`。管理员若添加含 Date 条件的 partial index，例如 `partialFilterExpression: { date: { $gte: new Date(...) } }`，恢复得到字符串条件，索引覆盖范围会改变。文档数据的哈希检查不检查索引语义，因此仍可报告成功。
- **影响边界：当前插件默认创建的普通索引不触发。** 这是合法自定义索引的恢复缺陷，不表示默认安装已发生数据损坏。
- 证据：真实 `backup/restore` 函数配合模拟 Mongo 与临时目录，原索引条件为 Date，恢复 `createIndexes` 收到 ISO 字符串；未连接真实 Mongo。复现脚本见下方验证说明。
- 建议：索引元数据同样使用能保留 BSON 类型的序列化，恢复后核对索引定义；或在备份阶段明确拒绝无法保真的索引，要求使用原生备份工具。补充 Date 等 BSON 条件的真实临时 Mongo 回归。

维护建议：`TrainingService` 同时承担同步、队列、参照导入、筛查与结算，属于 possible Divergent Change。可在后续修改同步状态机时逐步提取模块；这是维护性判断，不作为 1.0 的独立阻塞项。

本轴：1 项确定缺陷，最高 P2；1 项非阻塞维护建议。

## Spec

### F1 · P1 · 完整刷新失败后，普通重试丢失范围并接受旧成绩

- 位置：[service.js](../../lib/service.js)第 144—148 行；结算就绪判断为第 478—486 行。
- 需求：[T01](../plans/v1.0-tasks/01-sync-generation.md)要求“保留尚未满足的完整扫描需求”；[T02](../plans/v1.0-tasks/02-settlement-coverage.md)要求“无尚未满足的本场刷新请求”。
- 触发顺序：一周前的比赛已经取得完整扫描证明 g1，但尚未结算；CF 将原 AC 重测为 WA；教练发起完整刷新 g2，首个提交分页请求失败，尚无持久化 cycle；之后学生点击“刷新历史”或教练点击普通“同步”。
- `queueSync` 只在 queued/syncing 状态合并旧请求范围，failed 且 cycle 为空时丢掉 g2 的完整范围。新的 g3 仅扫描近期，完成后账号回到 ready。`result` 再选回 g1 证明，未重新读到旧比赛的 WA，却宣布可结算。
- 复现输出：远端 `WRONG_ANSWER`，本地 `OK`，`complete=true`、`eligible=true`、498 分；所选证明 generation 为 1，当前 generation 为 3。脚本调用真实 `queueSync/syncPage/result`，以顺序内存存储替代 Mongo，并模拟 `tick` 的失败状态转换；不是实际 CF 重测或真实数据库竞态实验。
- 修复方向：失败但未满足的完整请求仍参与范围合并；保存本场较新请求的待完成状态，不能用较旧证明消除该要求。同时保留无关窄窗口刷新复用旧有效证明的能力。
- 验收：以成功 g1 → 远端重测 → g2 首页失败 → 普通重试 g3 为正式回归，断言重试覆盖原比赛并得到 WA；实际完成前拒绝结算。覆盖失败发生在首请求、分页中途及进程重启后的路径。

### F2 · P1 · 训练详情迟到响应使操作指向另一场训练

- 位置：[cf_training_app.html](../../templates/cf_training_app.html)第 542—545、565、658—661 行；相关预览逻辑为第 670—674 行。
- 需求：[T07](../plans/v1.0-tasks/07-draft-lifecycle.md)的改期、取消应作用于指定草稿；README 的发布、换题及结算也均以所选训练为目标。
- `openRun(id)` 在请求返回前修改全局 `currentRun`，返回后直接渲染，没有序号检查。先打开 A，再打开 B，若 A 迟到，页面最终显示 A，但 `currentRun` 仍为 B。按钮和表单使用全局 ID 发起写操作。
- Edge + 当前真实模板 + 构造 API 已复现：可见标题为 `Training A`，点击“取消草稿”后发出的请求为 `{"action":"cancel_draft","id":"B"}`。后端无法从请求中识别用户看到的是另一场比赛。这会使教练取消错误草稿；同类目标错配还影响发布、资格修改、换题等入口。
- 修复方向：详情请求、预览和候选题请求使用请求序号并丢弃迟到响应；按钮目标与实际渲染的 run ID 绑定，切换加载时禁用或移除旧操作控件。仅增加取消确认弹窗不能修复目标错配。
- 验收：A 慢/B 快、A 快/B 慢、同场连续刷新、失败返回、预览期间切场、返回列表后迟到响应；每次写入 ID 必须与用户看到的目标一致。将构造复现转为期望安全行为的正式浏览器回归。

本轴：2 项确定缺陷，最高 P1；未发现额外确定的需求范围扩张。旧审查中已经修复的原始路径未重复计入。
