## 确定问题

### F1 · P2 · 宽泛选赛阻塞请求进程

位置：`lib/service.js:423`、`lib/core.js:147`。每个候选比赛、每个学生都重新扫描全部提交历史，直到筛查和排序完成才分页。调用实际 `discover`，以构造的 20 人、每人 3000 条提交、1500 场候选验证：返回 20 行耗时 4179 ms，期间零延时定时器未执行。该验证没有 Mongo 或网络开销，是构造复现，不是实际班级故障记录。

最小建议：每次请求先为各学生建立接触题、AC 题、参赛比赛集合，再筛查候选；保持 unknown、手工标记、时间边界、结果排序和分页语义。不能简单先分页，因为“仅无已知接触记录”筛选及排序依赖全体结果。无需持久缓存、新 worker 或新服务。

### F2 · P2 · 繁忙队列阻止赛中自动刷新入队

位置：`lib/service.js:614`。只有没有可运行 job 时才检查到期账号；首次全历史分页任务持续占用队列时，已同步参赛学生超过 60 秒也不会被安排刷新。实际 `tick` 配合构造队列、锁和时钟：120 个持续繁忙 tick、模拟 360 秒期间，到期参赛学生入队次数为 0；队列空闲后的下一 tick 才入队。

赛后显式完整同步和结算覆盖校验仍有效，本项不是已确认的结算数据错误。建议在现有锁内独立、节流检查到期账号，仅为没有未完成扫描的 ready 账号排队；不能反复重置 queued/syncing 账号代次，否则会干扰全量扫描。无需改成并发 CF 抓取或新任务平台。

### U1 · 计分规则未在详情中显示

位置：`templates/cf_training_app.html:565`、`:743`、`lib/student-response.js:7`。创建时可自定义 CF 衰减、错误扣分和 ICPC 罚时，创建后详情却不显示实际保存的规则，学生响应也没有规则类型和参数。建议只增加只读计分摘要，让教练发布前核对，学生知道本场规则；学生 API 继续使用白名单，不直接展开整个内部规则对象。

### U2 · 后台任务难以辨认目标

位置：`index.js:109`、`templates/cf_training_app.html:541`。任务显示类型、状态和错误，没有学生或比赛标签；同时导入两场或同步多人时无法对应。建议只补比赛 ID、学生标签、更新时间等必要信息。任务目标仍遵守现有身份边界，不向学生返回他人任务。完整进度面板可后置。

### T1 · 模板测试缺少加载等待

位置：`test/e2e/student-response.cjs:35`。点击详情后立即读取正文，会把正常加载占位误判为失败。七套模板测试并行运行时该项出现一次失败，单独复跑通过。建议等待最终详情文案后断言；复跑通过不能抹去首次失败，也不构成产品缺陷。

## 保留、推迟与删减意见

- 保留组赛、签到、接触筛查、可撤销结算、Rating、班级权限和恢复闭环。班级转让与图表虽然不是首次试训核心，已经实现并有测试，临上线删除会增加回归范围；冻结即可。
- 本轮只建议处理 F1/F2、U1/U2、T1。完整同步进度、容量提示、班级 CSV 和赛后复盘由真实内测反馈决定顺序。
- 不加推荐系统、更多数据源、特殊赛制、通用任务中心、存储分片、在线备份平台，不拆服务或重构全部 `TrainingService`。
- README/E2E 混有旧阶段日志和“待 T10”叙述，后续可将现状与历史记录分开，减少维护噪音；历史验收证据应保留，不逐轮复制进产品说明。
- 其他非阻塞项：赛后未结算详情仍显示签到按钮，服务端会拒绝；学生首页训练列表靠后；导入失败可能留下无引用参照分片；取消记录仍占 200 场容量。先记录真实影响，不借此扩大首发。

### 隔离边界

老师要求本次不得启动真实容器、不得使用真实 `oj-mongo`、不得修改真实容器配置。执行方式：

- 真实 daemon 停止期间启动**独立 dockerd 实例**（`--data-root /var/lib/docker-t10`、独立 exec-root，仅在真实 daemon 停止期间使用默认 socket）。镜像从现有 containerd 存储只读复制（无绝对路径引用）；隔离实例中 `docker ps -a` 为空，三个真实容器定义不可见、零自动启动。

- 固定测试库 `cftrain_test_t10_hydro_isolated`：隔离实例初始仅有 admin/config/local，确认未被其他工作使用；真实 mongo 数据目录中也不存在任何 `cftrain*` 数据库。清理后隔离实例恢复为仅 admin/config/local。
- 前后指纹一致：真实容器 `config.v2.json`/`hostconfig.json` 哈希、真实 mongo 数据目录时间与大小均未变；真实服务全程未启动（无进程、无 socket、无 docker0、端口 80/27017/18888 未监听）。隔离容器、卷、data-root 与本轮测试凭据已删除；另行清除隔离 daemon 遗留的 iptables 链与 MASQUERADE 规则（IPv4/IPv6 均为 0 条 docker 引用、无残留网桥；FORWARD 策略保持 DROP）。
