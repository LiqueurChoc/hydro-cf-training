# T01 · 修复同步代次与任务丢失

先读[执行约定](README.md)。依赖：无。对应 S2。

## 目标

正在运行的旧同步，不能覆盖或吞掉教练后来要求的完整比赛窗口扫描。重复刷新、任务重试和服务重启后，请求仍能执行。

## 实施范围

主要检查 `lib/service.js` 的 `syncPage`、`enqueue`、`tick` 和 `index.js` 的 `refresh_run`。先复现“挂起旧 user.status → 请求更早窗口 → 旧分页结束 → 新 cycle 被清空”。

建立明确的扫描代次和持久化请求状态。分页只能推进其所属代次；旧代次返回时不能把新代次标为 ready、清空其游标，或覆盖新一轮已经写入的提交 verdict。任务结束更新也必须核对任务代次/租约，不能只保护 account.cycle。

队列去重应保留尚未满足的完整扫描需求。合并扫描范围时保留需要更早起点的请求；比赛结束后提出的刷新需求不能被一轮赛前启动的扫描冒充完成。具体字段由实现决定，在交接中给 T02 写明启动、分页、失败、重试和完成契约。

兼容旧账号和旧排队任务；代次信息缺失时采取可恢复的重新排队/初始化，不要求手工改数据库。

## 验收

- 可控制请求完成顺序的测试证明旧分页不能覆盖新 cycle；旧空页、旧非空末页、旧请求失败均覆盖。
- 连续两次完整刷新不会丢请求；运行中去重后仍会扫描所需最早时间。
- 新旧任务交错时，旧写回不能覆盖较新的判题数据。
- 使用第二个服务实例模拟重启/租约恢复，能够继续待办扫描；验证真实 Mongo 条件写入语义。
- 保留已有分页重叠、CF 串行限速、账号换绑隔离；本任务不改结算资格规则。

## 交接
