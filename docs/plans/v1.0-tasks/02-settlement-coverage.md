# T02 · 以完整扫描覆盖约束结算

先读[执行约定](README.md)及 [T01 交接](01-sync-generation.md)。依赖：T01。对应 F1。

## 目标

只有得到本场完整、成功、赛后启动的扫描证明，才允许本次结算。近期普通同步时间不能代替比赛窗口覆盖。

## 实施范围

主要检查 `lib/service.js` 的同步完成、`result`、`preview`、`settle`，以及本场刷新接口和结算界面。

基于 T01 记录成功扫描的绑定身份、代次、扫描开始时间及实际覆盖下界；只有正常扫描至所需起点或历史末尾才能生成证明。失败或未完分页不能生成成功证明。空历史是有效情况，需要有实际读到末尾的依据。

本场可结算要求证明属于参赛快照的 bindingId、扫描在比赛结束后启动、覆盖至比赛开始，且无尚未满足的本场刷新请求及待判提交。明确处理多个训练窗口，避免只保留最新窄窗口导致有效旧证明无故丢失。已有已结算快照保持冻结；旧数据的未结算/撤销后重结算记录，需要重新取得证明。

预览令牌及确认条件应覆盖本次评分输入和扫描依据。预览后新扫描、重测、换绑或资格变化时，拒绝过期确认。界面具体解释缺少哪个条件，并保留可执行的本场刷新入口。

## 验收

- 一周前比赛 + 最近 24 小时增量刷新，仍不可结算；完整本场刷新后才可结算。
- 旧 AC 重测为 WA 后，完整刷新使计分与新 verdict 一致。
- 跨越比赛结束的扫描、失败扫描、空历史、分页边界、换绑、重复刷新、不同训练窗口均有验证。
- 在预览与确认之间改变同步依据或评分输入，旧 token 被拒绝；重复结算仍不能加两次分。
- 集成测试原有成功流程改为建立真实覆盖依据，不使用“伪填 lastSyncAt”绕过新规则。
