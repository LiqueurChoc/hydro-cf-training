## 所有任务的执行约定

1. 阅读适用 AGENTS.md、插件 README、当前任务及必要依赖的交接。涉及班级权限时阅读项目 CONTEXT 和 ADR 0002；涉及发布时阅读部署脚本和 E2E 说明。课程原始笔记仍为只读且不在本任务读取范围。
2. 先记录当前 Git 状态、检查相关 diff，保留已有改动和未跟踪文件。只修本任务，不顺带重构全项目、创建 GitHub Issues 或发布消息。不要用 reset/checkout 清理他人工作。
3. 对已报告缺陷先复现，再用正式测试表达期望行为。审查中的 `.test-output/` 脚本可能不存在；它们的断言用于证明旧缺陷，不能直接作为修复成功的标准。测试覆盖实际风险，不固定要求测试数量。
4. 兼容现有已保存数据。新字段需要明确旧数据默认值、失效/重建策略及回退影响。涉及评分时保留原计分算法、事件版本、基线和按结束时间重放顺序。
5. 修改对应 README 等行为文档；历史审查记录保持原样，通过任务交接说明修复情况。仅文档交接无需伪称已验证业务。若课程结构实际变化，遵循项目既有结构检查要求。
6. 验证使用构造数据、独立临时库或隔离测试环境；清理本任务临时数据并确认清理范围。正式 Hydro 的安装、重启、数据库恢复、推送标签与实际发布不在这些任务的默认执行范围，已有明确授权时以老师指令为准。
7. 每项完成后，在本任务末尾填写交接，并同步上表状态。依赖尚未完成则记录具体缺口，不把跳过测试、缺少环境或准备了脚本写成验证通过。

## 统一交接格式

每个任务文件只维护一份最终交接，后续修订更新该处：

- 状态：待执行 / 进行中 / 已完成 / 待外部验证。
- 实际修改：文件与关键行为；必要的数据字段/API 契约变更。
- 验证：执行命令、通过/失败/跳过、构造或真实环境、临时数据清理结果。
- 兼容与恢复：旧数据处理及回退限制；不适用时注明。
- 后续依赖：下一任务必须知道的接口、限制和未完成项；如有提交，记录 commit。
