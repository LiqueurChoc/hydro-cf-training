# T10 · 完整验收与准备发布包

先读[执行约定](README.md)及全部任务交接。依赖：T01—T09，包含 T08 明确口径。

## 目标

针对同一候选源码和包完成验证，交付可以追溯、可回退的 1.0 发布候选及发布判定。本任务默认不等于正式部署授权。

## 实施步骤与完成条件

1. **核对任务与工作树。** 每个审查项都有实现、正式回归及交接证据；必要运行文件被纳入候选包，既有未提交修改有清楚归属。发现未完成的 P1/P2，定位到对应任务并先修明确的验收缺陷；重大范围变化记录回原任务。
2. **自动回归。** 运行当前全量单测、真实临时 Mongo 集成、真实 CF API 和模板浏览器回归，记录命令与 pass/fail/skip；候选增加的新测试也纳入。环境不支持的检查单列，不能沿用旧 README 数字。
3. **真实 Hydro HTTP。** 用候选包在隔离 Hydro 实例/域验证学生、普通教练、受托学生管理员、所有者、域管理员、权限撤销及跨域请求。覆盖组赛、切班、替换题、发布、赛前隐藏、签到、同步、预览、结算、防重、撤销、误报纠正、草稿取消/改期、换绑和统计；检查原始响应隐私。只有创建临时域但仍加载旧插件不算候选验收。
4. **故障与负载。** 按 T01—T03 的场景重验同步中刷新、进程重启恢复、重测、缓存失效和多人查看；按 T09 复验故障回退与数据库恢复。记录范围与实测结果；构造数据标明性质。
5. **试训边界。** 自动化可用合成数据模拟完整训练，但不能冒充真实学生整场试训。整理老师的小班试训步骤和结果记录栏；未获得真实试训结果时标为“待试训”，明确技术验收与教学使用验收分别判断。
6. **候选交付。** 技术验证通过后设置 `1.0.0-rc.1`（如已有候选版本则合理递增）、写变更记录，输出包文件列表、校验值、兼容环境、备份/回退说明和剩余限制。若改版号或打包内容影响候选包，重新生成并核对实际交付包。记录 commit；若未提交则记录工作树内容摘要/清单和包校验值，不能用 HEAD 冒充完整候选来源。

最终判定使用“技术验收通过，待真实试训/发布”“待修复”或“满足已授权的发布条件”，并列出证据。全部条件满足且老师明确要求实际发布时，再升级为 `1.0.0`、创建/推送标签、安装与发布；这些操作不因完成任务列表自动发生。
