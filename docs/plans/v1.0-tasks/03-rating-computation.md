# T03 · 消除页面上的全量 Rating 重算

先读[执行约定](README.md)及 [T02 交接](02-settlement-coverage.md)。依赖：T02。对应 S1。

## 目标

查看主页和班级榜不再在 Hydro 请求线程重算全域全部评分；首次计算和失效重建也不会长时间阻塞其他请求。

## 实施范围

检查 `lib/service.js` 的 `replay`、`reference`、结算与基线初始化，以及 `index.js` 的 dashboard、preview、export 和班级榜调用路径。保留原评分函数作为重建与结果对照。

为派生评分建立稳定的版本键（覆盖有效结算输入、基线和算法版本），缓存完整一致的 Rating/曲线结果。结算、撤销、重新结算、初始评分补齐使对应缓存失效；同步状态、班名等无关更新不触发重算。版本与权威状态原子关联，失效竞态下旧计算不能被当作新结果发布。

昂贵计算放到 worker/后台执行，处理同一版本的请求合并，缓存内存及任务数有界。Hydro 多进程、重启后空缓存、worker 失败和旧数据均有恢复路径。计算期间页面显示状态，不将旧缓存伪装成最新结果；班级权限过滤每次仍按当前权限执行。

预览和导出也需避免同类同步阻塞，缓存不能使 T02 的 token/确认失效检查失真。本任务不修改“历史最高”的产品口径，留给 T08。

## 验收

- 新实现与原 replay 对相同数据结果一致，覆盖补基线、同结束时间排序、撤销及重结算。
- 构造 10 场 × 100 人 × 20,946 人参照池，报告冷/热读取、重建耗时和事件循环响应；注明硬件/Node 及构造数据。
- 缓存命中时不调用评分引擎；重建期间轻量请求/定时器仍能执行。
- 并发读取合并重复计算；旧版本结果不会覆盖新版本，worker 失败后可以重试。
- 多个服务实例及重启后的行为有验证，权限撤销后缓存不泄露资料。

- 版本与并发契约：版本键是同一次原子 state 快照的基线数值、有效事件评分输入、快照 ID、算法版本和缓存格式的摘要，不另存一个可能与 state 脱节的版本字段。冻结参照按 ID 不可变；显示元数据从调用方 state 装配。结算/撤销/重结算/补基线改变输入后切换版本，旧任务只写自己的版本；同输入复用计算不等于复用 token。同步、班名、扫描证明等不触发评分重建；T02 的 rows/证明/revision 仍参与新 token 和确认检查。每个进程 1 个 worker、最多 8 项运行/排队任务，LRU 最多 16 项/序列化 32 MiB，worker 老生代堆 256 MiB、执行超时 30 分钟；失败至少等待 1 秒后由下一次读取重试。多 Hydro 进程各自缓存与合并请求，可能各冷算一次，不依赖共享缓存或丢失的失效通知。
