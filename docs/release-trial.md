# 1.0 Preview 内部试训

状态：**`1.0.0-preview.2` 待真实小班试训**。本包只用于获准环境内部测试，不是正式 1.0。自动化使用合成账号、CF 提交与时间推进；技术验收不能代替真实学生整场使用或教学验收。测试通过并取得明确授权后，必须重新生成 `1.0.0` 正式包，不能直接沿用 preview 包。

首轮限定一个真实小班、1–2 名教练。真实账号绑定、训练成绩与本地 Rating 必须保留到后续版本；只有明确标记的测试数据可以清理。不要把参加 preview 理解为同意丢弃真实记录。真实试训在内测上线后完成，不要求先有试训结果才开始内测。

## 老师执行步骤

1. 在获准维护的环境核对候选包校验值，按[部署与恢复](deployment-recovery.md)完成停写备份、独立库恢复核对及安装。记录 Hydro/Node/Mongo 版本、候选哈希和恢复编号。
2. 选择少量自愿试训学生，绑定各自真实 CF 账号；完成全历史同步、老师确认归属、班级所有权与受托权限检查。确认未接触所选题目；历史未知者不计分放行。
3. 导入参照榜，选班、核对名单、换题及分值、改期并发布。学生验证赛前题目隐藏、签到，按统一时间在 CF 完成整场训练。记录同步失败、页面等待、手机显示和操作歧义。
4. 赛后请求本场完整同步，核对 CF 提交与 Hydro 榜单（含零解题者、缺席者及练习者），待预览完成后确认一次结算。检查有效训练历史最高与固定起点；发现错误时先撤销、纠正、重新完整同步和预览。
5. 核对班级榜、个人统计、导出和实际恢复可操作性。老师确认是否适合日常使用；失败记录复现条件，不以自动化通过覆盖真实问题。
